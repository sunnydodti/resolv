# OpenCode Conventional Commit Standards

## Commit Message Format

All commits must follow the Conventional Commits specification:

```
<type>(<scope>): <subject>

<body>

<footer>
```

### Components

- **type**: The kind of change (see Types below)
- **scope**: The area of the codebase affected (see Required Scopes below)
- **subject**: A concise description of the change (imperative mood, no capitalization, no period)
- **body**: Optional detailed explanation of the change
- **footer**: Mandatory breaking change notices and issue references

## Types

| Type | Description |
|------|-------------|
| `feat` | A new feature |
| `fix` | A bug fix |
| `docs` | Documentation only changes |
| `style` | Changes that do not affect the meaning of the code (white-space, formatting, missing semi-colons, etc.) |
| `refactor` | A code change that neither fixes a bug nor adds a feature |
| `perf` | A code change that improves performance |
| `test` | Adding missing tests or correcting existing tests |
| `build` | Changes that affect the build system or external dependencies |
| `ci` | Changes to CI configuration files and scripts |
| `chore` | Other changes that don't modify src or test files |
| `revert` | Reverts a previous commit |

## Required Scopes

The following directories require an explicit scope in every commit:

- `agents/` — Changes to agent configurations, prompts, or behaviors
- `core/` — Changes to core engine, runtime, or shared infrastructure
- `config/` — Changes to configuration files, settings, or environment setup

### Scope Examples

```
feat(agents): add code review agent
fix(core): resolve race condition in task scheduler
docs(config): update environment variable reference
refactor(agents): simplify prompt template rendering
```

If a change spans multiple required directories, use the primary affected scope or separate commits.

## Character Limits

- **type**: lowercase, max 10 characters
- **scope**: lowercase, max 50 characters, hyphen-separated words
- **subject**: max 72 characters (including type and scope prefix)
- **body lines**: max 72 characters per line
- **footer lines**: max 72 characters per line

## Mandatory Footer

Every commit message must include a footer with an issue reference:

```
Closes: #<issue-number>
```

or

```
Refs: #<issue-number>
```

### Footer Examples

```
Closes: #123
Refs: #456, #789
BREAKING CHANGE: The `agents/` configuration schema has changed.
```

The footer must appear after the body (or subject if no body), separated by a blank line.

## AI-Generated Commit Messages

For any commit message generated by AI tooling, you **must** invoke the commit generation script:

```
python scripts/generate_commit.py
```

Review and edit the generated message to ensure it conforms to these standards before committing.

## Examples

### Valid Commit

```
feat(agents): implement automated PR review agent

Add a new agent that reviews pull requests for style and correctness.
Includes configurable thresholds and comment templates.

Closes: #42
```

### Valid Commit with Breaking Change

```
fix(core): correct task queue priority handling

Reprioritize queued tasks based on urgency rather than insertion order.

BREAKING CHANGE: Task priority is now determined by the `urgency` field.
Closes: #88
```

### Invalid Commit (missing scope)

```
feat: add new feature
```

### Invalid Commit (subject too long)

```
feat(agents): this subject line is way too long and exceeds the seventy-two character limit for commit subjects
```
